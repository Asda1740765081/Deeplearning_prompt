# 架构与维护约定

`scripts/build.mjs` 使用 Node.js 标准库，将页面模板、样式、研究模板、纯逻辑和交互代码合成单文件 `index.html`。产物提交到 Git，GitHub Pages 无需运行构建命令。

`npm run build:check` 在内存中重建后比较文件，检测源文件与产物不同步。模板变化后执行 `npm run examples` 更新示例；`--check` 模式仅检查，不重写。

## 数据流

1. `data.js` 定义分类、模板和角色入口。
2. `app.js` 读取本地数据，渲染导航、筛选与卡片。
3. 选择模板后，用字段定义渲染输入。`core.js` 的 `renderPrompt` 一次性替换变量，保留输入中的特殊字符和相似变量文本。
4. 生成指令以文本显示，输入保存为草稿。复制、下载和备份由用户发起。
5. 导入先生成通过校验的候选集合，再合并关联数据。存储失败时明确提示，可导出当前内容。

没有后端、数据库、认证或服务端密钥。Playwright 是开发测试依赖，不打包到网页。

## 兼容性

保留 `dp-*` 存储键、旧版模板数组 / `customPrompts` JSON、`#share=` 链接。新备份版本为 3，拒绝未知版本以免错误解读。新分享默认不传填写材料。

稳定模板 ID 影响收藏、草稿和分享，尽量不要修改。历史网页备份和本机测试数据不要作为新模板提交。

## 内容维护

当前 33 个模板与 7 个角色的数量由测试核验。增加内容时同时更新测试和说明。难度是使用引导，不代表研究质量；个人评分也不是模型效果指标。

人工交接文档中的 Codex/DeepSeek 名称表示指令的预期用途，不代表本站与服务商存在自动集成或隶属关系。
