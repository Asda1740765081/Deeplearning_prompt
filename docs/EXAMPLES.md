# 三个可复现的操作案例

这些案例展示网站实际完成的“填写信息 → 生成完整提示词 → 交给外部工具使用”的流程。输入为项目自编的公开演示材料，不是用户研究记录、真实论文或实验结果。下列产物都是网站生成的提示词，未调用外部模型，也不声称已完成论文分析、代码修复或幻灯片制作。

输入原文与检查点见 [examples/cases.json](../examples/cases.json)。`npm run examples` 可重新生成全部指令，`npm run check` 会核对已提交的输出是否一致。

## 1. 论文筛选

**任务：** 在精读之前判断材料是否符合自己的研究方向。

**输入：** 自编的小样本图像分类摘要与调研目标。摘要只描述“固定编码器 + 近邻检索”设想，没有数据集、性能数字或公开代码。

**操作：** 搜索“三分钟速读”，将 `paper-screening` 的 `abstract` 填入“标题与摘要”，将 `goal` 填入“当前调研目标”。

**实际生成：** [完整提示词](../examples/outputs/paper-screening.txt)，保留材料和目标，要求按问题、方法、相关度、精读建议等结构输出。浏览器测试逐字比对结果。

**后续使用：** 复制到你选择的 AI 工具，检查回答是否承认缺失证据，再决定是否寻找完整论文。模型给出的可靠性或新颖性分数只是辅助判断，并非经验证的质量指标。

**限制：** 网站没有检索论文、验证引用或证明方法有效。演示摘要不足以支持任何性能结论。

## 2. 训练异常诊断

**任务：** 将“训练报错”变成含最小代码和验证要求的诊断任务。

**输入：** 一维 Float 类别标签、形状 `[4, 3]` 的 logits，以及 `CrossEntropyLoss` 类型错误演示日志。输入明确声明尚未运行修复。

**操作：** 搜索“训练异常诊断”，将 `training-diagnosis` 的 `symptom` 与 `code` 分别填入异常和代码字段。

**实际生成：** [完整提示词](../examples/outputs/training-diagnosis.txt)，保留错误和代码，要求支持/反对证据、最小验证、最小修复与排查顺序。

![训练诊断示例的填写与预览](screenshots/editor.png)

**后续使用：** 复制给 AI 工具获取建议，人工检查标签语义、类别范围与数据类型，在自己的隔离环境运行最小验证，再考虑改训练代码。

**限制：** 网站不执行 PyTorch、不连接代码仓库，也没有验证修复效果。案例验证的是材料进入指令的过程。

## 3. 组会汇报规划

**任务：** 将零散笔记组织成有时间限制的研究汇报。

**输入：** 自编周记，包含数据划分、类型错误、未完成的训练，以及“没有可报告准确率”的记录；要求 8 分钟、6 页以内。

**操作：** 搜索“组会周报 PPT”，填写 `weekly-research-report` 的 `work` 和 `context`。

**实际生成：** [完整提示词](../examples/outputs/weekly-research-report.txt)，要求每页结论、要点、视觉建议、时间、失败记录与下周计划，缺失信息保持待补充。

**后续使用：** 复制到 AI 工具获得讲述草案，核对每项进展和数字，按实际证据补齐内容，再使用幻灯片工具制作文件。

**限制：** 网站准备汇报规划指令，不导出 PPTX，也不证明实验已完成。

## 本地复现

```sh
npm ci
npm run build
npm run examples
npm run check
npx playwright install chromium
npm run test:e2e
```

核心测试核对输出文件；浏览器测试将同一输入真正填进页面，检查完整预览。没有模型采样，输入与模板相同，指令文本应一致。后续模型回答可能变化，需要另行审核。

欢迎按[贡献指南](../CONTRIBUTING.md)提供经授权的真实案例：公开输入来源、实际使用方式和人工验证步骤，明确哪些效果经过运行确认，不用演示代替用户证言。
